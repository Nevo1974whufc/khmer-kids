# YouTube API compliance audit — copy-paste answers

Open: **https://support.google.com/youtube/contact/yt_api_form**
(You may need to sign in with the Google account that owns the channel and the
Google Cloud project.)

Where it asks for your **project number / ID**: Google Cloud Console
(https://console.cloud.google.com) → top bar next to "Google Cloud" → the project
you enabled YouTube Data API v3 in. Copy the number.

---

**Use-case description (paste this, edit the bracketed bits):**

> I run a single educational YouTube channel, [CHANNEL NAME], that teaches children
> in Cambodia basic English vocabulary through short original animated episodes.
> I am the sole creator and I own all content: the animation is generated by my own
> automated pipeline from my own locked character artwork, and the audio is
> synthetic speech of my own script text. Nothing is copied from other creators.
>
> My application calls only one endpoint: videos.insert, exactly once per day, from
> a scheduled GitHub Actions job on my own repository, to upload that day's episode
> to my own channel. Videos are set to public and are marked "made for kids"
> (selfDeclaredMadeForKids=true). No other API methods are used, no search calls,
> no bulk operations, no third-party users, no OAuth for anyone but myself.
>
> Daily usage is approximately 1,600 quota units, far below the default 10,000.
> I am NOT requesting additional quota — I am submitting this audit so that my
> once-daily upload is published publicly instead of being locked to private.
> I agree to the YouTube API Services Terms of Service and the Children's Online
> Privacy Protection Act requirements for made-for-kids content.

**Anything else they ask:**
* "Will you use quota above 10,000/day?" → **No.**
* "Does your app serve other users?" → **No, only my own channel.**
* "Privacy policy URL?" → a personal project may leave blank; if required, create a
  free one-page site (e.g. GitHub Pages) saying "this app only uploads videos to the
  owner's own YouTube channel and stores no user data."

After approval you get an email; then run `scripts/setup_once.*` to switch on
auto-upload. Until then, uploads via the API stay private — so don't bother enabling
auto-upload before the email arrives.
